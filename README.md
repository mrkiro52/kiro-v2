# KIRO Platform v2.0

KIRO Platform — образовательная платформа IT-лагеря. Сейчас мы собираем её новую версию.

Задачи — в [GitHub Project](https://github.com/users/mrkiro52/projects/1) и в [docs/tasks/](docs/tasks/README.md). Метка `start-now` означает, что задачу можно брать сразу.

## Этап 1

Сейчас идёт только первый этап. В него входят три части.

**1. Архитектура**
- Сервисы и их границы: Gateway, Auth, Users, Social. У каждого сервиса своя база данных; сервисы общаются через API и события.
- Контракты API (OpenAPI) пишутся до кода.
- Монорепозиторий, локальное окружение, CI, staging, мониторинг.
- Безопасность встроена в процесс разработки (см. SSDLC ниже).

**2. Авторизация и регистрация**
- Регистрация, вход и выход, восстановление доступа, смена пароля.
- Роли: студент, куратор, администратор.

**3. Социальная сеть**
- Профиль: аватар, «о себе», ссылки, настройки приватности, страница чужого профиля.
- Посты: создание, редактирование, удаление.
- Комментарии и ответы на комментарии.
- Лайки на посты и комментарии.
- Лента и посты пользователя.
- Жалобы и модерация в админке.

Решения фиксируются в ADR (`docs/adr/`).

## SSDLC

Процесс безопасной разработки описан в [docs/security/ssdlc.md](docs/security/ssdlc.md). Главное для каждого:
- Требования безопасности входят в задачу и её критерии готовности.
- В PR автоматически запускаются проверки: анализ кода, поиск секретов, проверка зависимостей и образов.
- Подтверждённые уязвимости High и Critical блокируют выпуск, пока их не исправят или не оформят исключение.
- У найденных уязвимостей есть сроки исправления; исключения согласуются с ИБ и продакт-владельцем.


## Как поднять окружение с нуля

Поднимаются PostgreSQL, Redis, RabbitMQ и Traefik (заглушка Gateway). Первый запуск занимает около 10 минут, в основном это скачивание образов.

**Нужно установить:** [Git](https://git-scm.com/), [Docker Desktop](https://www.docker.com/products/docker-desktop/) (запущенный) и `make`. На Windows команды выполняются в Git Bash; если `make` не найден, установи его через `winget` или `choco` или используй команды из блока «Без make».

**1. Клонируй репозиторий и запусти окружение**

```bash
git clone https://github.com/mrkiro52/kiro-v2.git
cd kiro-v2
make up
```

`make up` сам создаст файл `.env` из `.env.example`. Для локальной работы значения по умолчанию подходят. Файл `.env` не коммитится.

**2. Проверь, что всё поднялось**

```bash
make ps
```

У `db`, `redis` и `broker` должен быть статус `healthy` (сразу после запуска может быть `starting`, подожди до 30 секунд).

| Сервис | Адрес | Логин / пароль |
| --- | --- | --- |
| PostgreSQL | `localhost:5432` | `kiro` / `change_me`, база `kiro` |
| Redis | `localhost:6379` | без пароля |
| RabbitMQ | http://localhost:15672 | `kiro` / `change_me` |
| Traefik | http://localhost:8080 | без пароля |


**Базы данных сервисов** создаются автоматически при первом запуске:

| Сервис | База | Пользователь | Пароль |
| --- | --- | --- | --- |
| auth | `auth` | `auth` | `AUTH_DB_PASSWORD` из `.env` |
| users | `users` | `users` | `USERS_DB_PASSWORD` из `.env` |
| social | `social` | `social` | `SOCIAL_DB_PASSWORD` из `.env` |

Каждый сервис подключается только к своей базе. Скрипт создания (`infra/postgres/init/`) выполняется только при первом создании тома. Чтобы пересоздать базы, выполни `down -v` (см. «Без make»), затем `make up`: данные будут потеряны.


**3. Останови окружение**

```bash
make down
```

Данные баз сохраняются. Остальные команды: `make logs` (логи, выход `Ctrl+C`) и `make ps` (статус).

<details>
<summary>Без make</summary>

```bash
cp .env.example .env
docker compose --env-file .env -f infra/docker-compose.yml up -d
docker compose --env-file .env -f infra/docker-compose.yml down
```

Полный сброс вместе с данными баз: добавь `-v` к `down`.

</details>

**Если что-то не работает**

| Ошибка | Что делать |
| --- | --- |
| `Cannot connect to the Docker daemon` | Запусти Docker Desktop |
| `port is already allocated` | Порт занят: останови программу или поменяй порт. Для PostgreSQL добавь в свой `.env` строку `POSTGRES_PORT=5433` (подойдёт любой свободный порт) |
| `missing separator` | В `Makefile` команды должны начинаться с Tab, а не с пробелов |
| Контейнер `unhealthy` или `Exited` | Посмотри `make logs`, причина обычно в последних строках |
| Баз `auth`, `users`, `social` нет, в `make logs` ошибки про `\r` или `bad interpreter` | Скрипт `infra/postgres/init/*.sh` сохранён с CRLF: переведи файл в LF (в VS Code переключатель справа внизу), затем `down -v` и `make up` |
| Баз `auth`, `users`, `social` нет, ошибок нет | Скрипт выполняется только на пустом томе: выполни `down -v`, затем `make up` (данные будут потеряны) |
