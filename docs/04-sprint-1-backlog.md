# Бэклог спринта 1: авторизация, регистрация, соцсеть

**Milestone:** 1 Проектирование · **Итерация:** 1–2

## Объём
- регистрация и вход;
- профиль: аватар, «о себе», ссылки, приватность;
- посты, комментарии, ответы на комментарии;
- лайки на посты и комментарии;
- лента и посты пользователя.

## Порядок (волны)
```
Волна 1: SA-1, BA-1, BA-2*, BA-3, DEV-1, DEV-2, SEC-4
Волна 2: BA-4, SA-2, SA-3, SEC-1, DEV-3
Волна 3: SA-4, SEC-2, SEC-3, DEV-4
Волна 4: SA-5
Волна 5: DEV-5
```
\* BA-2 в исходном плане не указан в волнах; логично начинать вместе с BA-1/BA-3 (см. [открытые вопросы](06-open-questions.md)).

## Бизнес-аналитики (Team: Learning/Growth)

### BA-1 Процессы регистрации и входа
- Зависит от: —
- Результат: схемы процессов (регистрация, вход, восстановление доступа, выход), роли, статусы пользователя.
- Готово, когда: процессы согласованы с продакт-владельцем и ИБ.

### BA-2 Процессы соцсети и модерация
- Зависит от: —
- Результат: процессы постов, комментариев, ответов, лайков; жалобы и модерация; правила видимости.
- Готово, когда: описаны роли (студент, куратор, админ) и сценарии модерации.

### BA-3 Требования к профилю
- Зависит от: —
- Результат: поля профиля (аватар, «о себе», ссылки), настройки приватности, ограничения и валидации.
- Готово, когда: требования проверены ИБ (персональные данные, 152-ФЗ).

### BA-4 Пользовательские истории MVP
- Зависит от: BA-1, BA-2, BA-3
- Результат: user stories с критериями приёмки по всему объёму спринта.
- Готово, когда: истории приоритизированы и разложены по сервисам.

## Системные аналитики (Team: Platform/Learning)

### SA-1 Структура документации и шаблоны
- Зависит от: —
- Результат: структура `docs/`, шаблоны ADR, описания сервиса, API, события.

### SA-2 Глоссарий и доменная модель
- Зависит от: BA-4 (частично BA-1..3)
- Результат: глоссарий терминов, доменная модель (User, Profile, Post, Comment, Like; позже Cohort/Enrollment).

### SA-3 Границы сервисов Auth / Users / Social и события
- Зависит от: BA-4, SA-2
- Результат: ответственность каждого сервиса, список событий (напр. `user.registered`, `post.created`), что кто хранит.
- Правило: сервис не читает чужую БД.

### SA-4 Схемы БД
- Зависит от: SA-3
- Результат: схемы PostgreSQL для Auth, Users, Social (у каждого сервиса своя БД).

### SA-5 OpenAPI-контракты
- Зависит от: SA-4, SEC-2, SEC-3
- Результат: OpenAPI в `contracts/` для Auth, Users, Social.
- Готово, когда: контракты прошли ревью разработчика и ИБ.

## ИБ (Team: Security)

### SEC-1 Threat model
- Зависит от: SA-3
- Результат: модель угроз по Auth, профилю, соцсети, загрузке файлов.

### SEC-2 Требования к Auth
- Зависит от: SEC-1
- Результат: хранение паролей, токены и сессии, блокировки, rate limit, восстановление доступа.

### SEC-3 Требования к контенту и файлам
- Зависит от: SEC-1
- Результат: валидация и санитизация контента, загрузка аватаров, права доступа, приватность.

### SEC-4 Проверки безопасности в CI
- Зависит от: —
- Результат: gitleaks, проверка зависимостей, Semgrep/CodeQL в GitHub Actions.

## Разработчики (Team: Platform)

### DEV-1 Стек и шаблон сервиса (ADR)
- Зависит от: —
- Результат: ADR по языку/фреймворку, структура шаблона сервиса, соглашения.

### DEV-2 Монорепозиторий и локальное окружение
- Зависит от: —
- Результат: `kiro-v2` со структурой `services/ frontend/ admin/ contracts/ infra/ docs/`, CODEOWNERS, Docker Compose для локалки.

### DEV-3 CI
- Зависит от: DEV-2 (и SEC-4)
- Результат: GitHub Actions, сборка только изменённых сервисов.

### DEV-4 Макеты в Figma
- Зависит от: BA-4 (и BA-3)
- Результат: макеты регистрации, входа, профиля, ленты, поста с комментариями.
- Опора: `docs/kiro-design-system.md` из v1.

### DEV-5 Прототип сервиса Auth
- Зависит от: SA-5, DEV-1, DEV-3
- Результат: рабочий прототип Auth по контракту OpenAPI (регистрация, вход).
