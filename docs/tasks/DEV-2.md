# DEV-2 Монорепозиторий и локальное окружение

**Исполнитель:** Бэкендер / DevOps · **Волна:** 1 · **Зависит от:** — (можно начинать сразу)

## Зачем
Все участники должны работать в одном репозитории с одинаковым локальным окружением, иначе «у меня работает» съест время спринта.

## Что нужно на входе
- `docs/01-context.md` — структура монорепо и правила
- Решение по стеку из DEV-1 (можно начинать параллельно, стек подставится позже)

## Что сделать
1. Создать структуру: `services/`, `frontend/`, `admin/`, `contracts/`, `infra/`, `docs/`.
2. Настроить `CODEOWNERS` по командам (Platform, Learning, Growth, Data & AI, Security).
3. Настроить защиту `main` (PR, ревью, обязательные проверки), шаблоны issues в `.github/ISSUE_TEMPLATE/` и шаблон PR.
4. Подготовить `infra/docker-compose.yml` для локального запуска: PostgreSQL, Redis, брокер, Traefik/Gateway-заглушка.
5. Добавить `.editorconfig`, `.gitignore`, `.env.example`, `Makefile`/скрипты (`make up`, `make down`).
6. Написать `README` с инструкцией «как поднять окружение с нуля».

## Что должно получиться
- Структура каталогов в `kiro-v2`
- `.github/CODEOWNERS`, `.github/ISSUE_TEMPLATE/*`, `.github/pull_request_template.md`
- `infra/docker-compose.yml`, `.env.example`, `Makefile`
- README с инструкцией

## Критерии готовности
- [ ] Новый участник поднимает окружение по README за ≤30 минут.
- [ ] Прямой push в `main` запрещён.
- [ ] CODEOWNERS работает (проверено тестовым PR).
- [ ] Документ проверен хотя бы одним человеком, который не писал инструкцию.

## С кем согласовать
Platform-лид, Архитектор, ИБ (SEC) — по защите ветки и секретам

## Вне объёма
CI-пайплайны — DEV-3. Серверы reg.ru — этап 0.

> Места, помеченные «предложение» или «предложить», — рекомендации аналитика, которые исполнитель должен проверить и подтвердить с владельцем решения.
