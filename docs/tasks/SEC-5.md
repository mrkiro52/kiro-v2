# SEC-5 Проверка безопасности реализации MVP

**Исполнитель:** Специалист ИБ · **Этап 3 (MVP)** · **Зависит от:** DEV-8 (#21), DEV-10 (#23), DEV-13 (#26), SEC-1 (#11)

## Зачем
Нужно убедиться, что реализация соответствует threat model и требованиям SEC-2/SEC-3.

## Что нужно на входе
- `docs/security/threat-model.md`, `auth-requirements.md`, `content-requirements.md`
- Рабочий стенд staging

## Что сделать
1. Провести ревью кода Auth, Users, Social, Gateway по чек-листу из требований.
2. Проверить авторизацию на каждом эндпоинте (доступ к чужим данным, обход приватности, повышение прав).
3. Проверить Auth: перебор, токены, восстановление, перечисление пользователей.
4. Проверить контент и файлы: XSS, загрузка вредоносных файлов, IDOR, rate limit.
5. Проверить конфигурацию: секреты, заголовки, порты, TLS, права в БД и S3.
6. Оформить отчёт, заведи issues на найденные проблемы с приоритетами; обновить threat model.

## Что должно получиться
- `docs/security/review-mvp.md`
- Issues по найденным уязвимостям

## Критерии готовности
- [ ] Нет уязвимостей Critical/High или они закрыты/принято решение.
- [ ] Все пункты threat model отмечены: исправлено/принято.
- [ ] Отчёт согласован с архитектором и продакт-владельцем.

## С кем согласовать
Архитектор, Продакт-владелец

## Вне объёма
Внешний пентест — по решению продакт-владельца.

> Места, помеченные «предложение» или «предложить», — рекомендации, которые исполнитель проверяет с владельцем решения.
