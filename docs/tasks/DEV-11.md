# DEV-11 Social: посты, комментарии, ответы на комментарии

**Команда:** Бэкенд · **Исполнитель:** Бэкендер · **Старт:** после DEV-5 (#18), DEV-6 (#19), DEV-7 (#20), DEV-9 (#22)

## Зачем
Ядро соцсети: создание и просмотр постов, комментарии и ответы на комментарии. Должно работать с учётом приватности и прав.

## Что нужно на входе
- `contracts/social.openapi.yaml` (DEV-22)
- `docs/db/social.md` (DEV-21)
- `docs/processes/social-*.md` (BA-2)
- События Users для данных автора

## Параллельные входы (не блокируют)
- BA-2 (#3)
- SEC-3 (#15)

Эти результаты делаются параллельно, часто другими командами. **Не жди их**: работай по объёму спринта и общим практикам, допущения запиши в своём документе. Когда результат появится — сверь и поправь (обычно это небольшие правки).

## Что сделать
1. Создать `services/social/` из шаблона, миграции по схеме DEV-21.
2. Реализовать API постов: создание, чтение, редактирование, удаление (мягкое), валидации и санитизация по SEC-3.
3. Реализовать комментарии и ответы на комментарии с выбранной вложенностью (BA-2), пагинацию, сортировку.
4. Получать данные автора (имя, аватар) по событиям Users и кэшировать локально (решение DEV-20).
5. Реализовать проверку прав: автор, куратор, админ; учёт приватности профиля.
6. Публиковать события `post.created`, `comment.created`, `post.deleted` и др.
7. Тесты: юнит, интеграционные, контрактные, права доступа.

## Что должно получиться
- `services/social/` с кодом, тестами, README
- Миграции БД

## Критерии готовности
- [ ] Все эндпоинты постов и комментариев по контракту реализованы.
- [ ] Ответ на комментарий корректно привязан к родителю; глубина ограничена.
- [ ] Права проверяются: чужой пост нельзя изменить; приватные данные не утекают.
- [ ] Контрактные тесты зелёные.
