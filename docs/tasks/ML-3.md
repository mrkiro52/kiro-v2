# ML-3 Правила работы с данными и внешними LLM

**Команда:** ML · **Исполнитель:** ML-разработчик + ИБ (ревью) · **Старт:** **сразу**

## Зачем
ML-команде нужны данные, но по 152-ФЗ можно работать только с обезличенными. Правила нужно зафиксировать до любой выгрузки.

## Что нужно на входе
- Ограничения из `docs/01-context.md` (обезличенная выгрузка, без идентификаторов во внешние LLM)
- Схема данных v1 (`backend/src/db.js`)

## Параллельные входы (не блокируют)
- SEC-6 (#36)

Эти результаты делаются параллельно, часто другими командами. **Не жди их**: работай по объёму спринта и общим практикам, допущения запиши в своём документе. Когда результат появится — сверь и поправь (обычно это небольшие правки).

## Что сделать
1. Определить, какие поля считаются персональными данными и как их обезличивать (удаление, хэширование с солью, обобщение).
2. Описать процесс выгрузки: кто делает, где хранится, срок хранения, кто имеет доступ, как удаляется.
3. Описать правила для внешних LLM: какие данные можно отправлять, фильтрация идентификаторов перед отправкой, логирование, выбор провайдера.
4. Подготовить скрипт обезличенной выгрузки (на тестовых данных) и проверку, что идентификаторов не осталось.
5. Получить ревью ИБ.

## Что должно получиться
- `docs/ml/data-rules.md`
- Скрипт обезличивания в `services/ai/tools/` или `infra/ml/` (по договорённости с бэкендом)

## Критерии готовности
- [ ] ИБ одобрил правила.
- [ ] Скрипт проверен: в выгрузке нет имён, email, телефонов, ссылок на профили.
- [ ] Правила понятны без устных пояснений.
