# BA-3 Требования к профилю

**Исполнитель:** Бизнес-аналитик · **Волна:** 1 · **Зависит от:** — (можно начинать сразу)

## Зачем
Профиль — основа соцсети и данных пользователя. Нужно решить, какие поля есть, что публично, какие есть ограничения. Это же определяет, какие персональные данные хранятся (152-ФЗ).

## Что нужно на входе
- Профиль в v1 (посмотреть платформу и `backend/` старого репозитория)
- Результаты BA-1 (статусы, роли) и BA-2 (видимость)
- 152-ФЗ: что считается персональными данными

## Что сделать
1. Составить таблицу полей профиля: аватар, «о себе», ссылки, имя/ник, направление (из Enrollment — только отображение), прочее. Для каждого поля: тип, обязательность, лимиты, валидации, публичное/приватное.
2. Описать ограничения: размер/формат аватара, длина «о себе», допустимые типы ссылок (GitHub, Telegram и т.п.), запрещённые домены.
3. Описать приватность: уровни (все / только лагерь / только я) и что они скрывают (профиль, посты, ссылки).
4. Описать процессы: редактирование профиля, смена аватара, удаление аватара, просмотр чужого профиля.
5. Передать ИБ список персональных данных на проверку.

## Что должно получиться
- `docs/requirements/profile.md` — таблица полей и правила приватности
- `docs/processes/profile.md` — сценарии работы с профилем

## Критерии готовности
- [ ] Для каждого поля указаны тип, лимиты, валидации и видимость.
- [ ] Уровни приватности описаны с примерами «кто что видит».
- [ ] ИБ подтвердил список ПДн и сроки хранения.
- [ ] Продакт-владелец принял требования.

## С кем согласовать
Продакт-владелец, ИБ (SEC)

## Вне объёма
Фото-модерация, подписки, друзья — не входят в спринт 1.

> Места, помеченные «предложение» или «предложить», — рекомендации аналитика, которые исполнитель должен проверить и подтвердить с владельцем решения.
