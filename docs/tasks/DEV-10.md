# DEV-10 Аватары: загрузка и хранение в S3

**Исполнитель:** Бэкендер · **Этап 3 (MVP)** · **Зависит от:** DEV-9 (#22), SEC-3 (#15)

## Зачем
Пользователи должны загружать аватар. Файлы — частая точка уязвимостей, поэтому нужны строгие проверки и хранение в объектном хранилище, а не в БД.

## Что нужно на входе
- S3-бакеты по окружениям (создаются на этапе 0, `docs/03-project-setup.md`)
- `docs/security/content-requirements.md` (SEC-3)
- Контракт Users

## Что сделать
1. Настроить доступ сервиса к S3 (отдельные ключи по окружениям, минимальные права).
2. Реализовать загрузку: проверка размера, типа по содержимому, перекодирование изображения, удаление метаданных, генерация имени.
3. Реализовать выдачу: публичный URL через CDN/прокси или подписанные ссылки с ограниченным сроком — решение зафиксировать в ADR.
4. Реализовать удаление и замену аватара, очистку старых файлов.
5. Добавить лимиты на частоту загрузок.
6. Написать тесты: корректные файлы, подделанное расширение, огромный файл, SVG/исполняемый контент.

## Что должно получиться
- Изменения в `services/users/`
- Конфигурация S3 в `infra/`
- `docs/adr/00NN-avatars-storage.md`

## Критерии готовности
- [ ] Подмена расширения или вредоносный файл отклоняется.
- [ ] Аватар отображается в профиле, старый удаляется.
- [ ] Ключи S3 не попадают в репозиторий и логи.
- [ ] ИБ подтвердил соблюдение SEC-3.

## С кем согласовать
ИБ (SEC), Platform-лид

## Вне объёма
Хранение других типов файлов (вложения к постам) — вне объёма.

> Места, помеченные «предложение» или «предложить», — рекомендации, которые исполнитель проверяет с владельцем решения.
