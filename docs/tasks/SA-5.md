# SA-5 OpenAPI-контракты

**Исполнитель:** Системный аналитик · **Волна:** 4 · **Зависит от:** SA-4 (#13), SEC-2 (#14), SEC-3 (#15)

## Зачем
По правилу v2.0 сначала контракт, потом код. Контракты — единственный источник правды для фронтенда и бэкенда; по ним разработчики независимо начинают работу.

## Что нужно на входе
- SA-4 (схемы БД), SEC-2 и SEC-3 (требования)
- SA-3 (границы и события), BA-4 (истории)
- Соглашения из DEV-1 (формат ошибок, версионирование)

## Что сделать
1. Описать OpenAPI 3.x для Auth: регистрация, вход, выход, обновление токена, восстановление доступа, смена пароля.
2. Описать OpenAPI для Users: профиль (получить/обновить), аватар, настройки приватности.
3. Описать OpenAPI для Social: посты, комментарии (с ответами), лайки, лента, посты пользователя, жалобы.
4. Для каждого метода: схемы запросов/ответов, коды ошибок, авторизация, пагинация, лимиты, примеры.
5. Описать схемы событий (AsyncAPI или JSON Schema) по каталогу из SA-3.
6. Прогнать lint (Spectral) и устранить замечания; согласовать с фуллстаком и бэкендером.

## Что должно получиться
- `contracts/auth.openapi.yaml`, `users.openapi.yaml`, `social.openapi.yaml`
- `contracts/events/*.json` (схемы событий)
- `contracts/README.md` — правила изменения контрактов

## Критерии готовности
- [ ] Lint без ошибок.
- [ ] Все требования SEC-2 и SEC-3 отражены в контракте (коды ошибок, лимиты, авторизация).
- [ ] Фуллстак и бэкендер подтвердили, что по контракту можно работать без уточнений.
- [ ] ИБ проверил контракты.

## С кем согласовать
Бэкендер, Фуллстак, ИБ (SEC), Архитектор
