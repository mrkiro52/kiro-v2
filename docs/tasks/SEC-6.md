# SEC-6 Безопасная настройка доступов, секретов и серверов

**Команда:** ИБ · **Исполнитель:** Специалист ИБ · **Старт:** **сразу**

## Зачем
До того как появится код и серверы, нужно договориться, как выдаются доступы и хранятся секреты. Это защищает проект с первого дня и не зависит от других команд.

## Что нужно на входе
- Чек-лист этапа 0 в `docs/03-project-setup.md`
- Репозиторий `kiro-v2`, GitHub Projects, серверы reg.ru (по мере появления)

## Что сделать
1. Описать модель доступов: кто из команд какие права получает в GitHub (организация, репозиторий, Projects, Environments), на серверах и в S3; принцип минимальных прав.
2. Описать правила работы с секретами: только GitHub Environments/Secrets и менеджер паролей, ротация, что делать при утечке.
3. Подготовить чек-лист настройки сервера: SSH только по ключам, отключение входа root и паролей, файрвол, автообновления безопасности, fail2ban или аналог, бэкапы и проверка восстановления.
4. Подготовить требования к защите `main` и к ревью (обязательные проверки, CODEOWNERS для `infra/` и `.github/`).
5. Включить 2FA для всех участников GitHub-организации и проверить.
6. Провести короткий инструктаж для команды (15–20 минут) по этим правилам.

## Что должно получиться
- `docs/security/access-and-secrets.md`
- `docs/security/server-hardening-checklist.md`

## Критерии готовности
- [ ] Правила доступов и секретов опубликованы и понятны без ИБ.
- [ ] У всех участников включена 2FA.
- [ ] Чек-лист сервера применён к staging (вместе с бэкендом, DEV-18) или готов к применению.
- [ ] Инструктаж проведён.
