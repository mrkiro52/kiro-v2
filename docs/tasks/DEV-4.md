# DEV-4 Макеты в Figma

**Исполнитель:** Фуллстак / дизайнер · **Волна:** 3 · **Зависит от:** BA-4 (#8)

## Зачем
Макеты нужны, чтобы команда, продакт-владелец и ИБ согласовали интерфейс до написания фронтенда. Должны опираться на дизайн-систему v1.

## Что нужно на входе
- BA-4 (пользовательские истории), BA-3 (поля профиля)
- [`docs/design/kiro-design-system.md`](../design/kiro-design-system.md)
- Существующий интерфейс платформы v1

## Что сделать
1. Составить список экранов по историям: регистрация, вход, восстановление, профиль (просмотр/редактирование), лента, пост с комментариями и ответами, мои посты, жалоба.
2. Сделать макеты для desktop и mobile; использовать компоненты дизайн-системы, недостающие — оформить новыми.
3. Показать состояния: пусто, загрузка, ошибка, валидация, приватный профиль, нет прав.
4. Подготовить кликабельный прототип основных сценариев.
5. Собрать ревью от BA, продакт-владельца и ИБ (какие данные видит пользователь).

## Что должно получиться
- Файл в Figma (ссылка в задаче и в `docs/design/README.md`)
- Список экранов с привязкой к историям

## Критерии готовности
- [ ] Все экраны покрывают истории MVP.
- [ ] Есть состояния ошибок и пустых данных.
- [ ] Продакт-владелец утвердил макеты.
- [ ] Макеты соответствуют дизайн-системе.

## С кем согласовать
Продакт-владелец, Бизнес-аналитик, ИБ (SEC)

## Вне объёма
Вёрстка и реализация фронтенда — следующие этапы.

> Места, помеченные «предложение» или «предложить», — рекомендации аналитика, которые исполнитель должен проверить и подтвердить с владельцем решения.
