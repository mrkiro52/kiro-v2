# SEC-10 ASOC: единый учёт находок (DefectDojo)

**Команда:** ИБ · **Исполнитель:** Специалист ИБ / DevSecOps · **Старт:** после SEC-7 (#44)

## Зачем
Находки от разных сканеров нужно собирать в одном месте, убирать дубли, назначать владельцев и контролировать сроки исправления. Процесс находок — [SSDLC KIRO v2](../security/ssdlc.md), раздел 7.

## Что нужно на входе
- SEC-0, SEC-7 (проверка DefectDojo)
- Правила обработки находок и сроки из `docs/security/ssdlc.md`

## Параллельные входы (не блокируют)
- SEC-4 — сканеры в CI, отчёты которых импортируются
- SEC-6 — доступы к серверу

Не ждать: работать по допущениям, сверить, когда результат появится.

## Что сделать
1. Развернуть DefectDojo Community (сначала на staging-сервере или отдельной VM), закрыть доступ, настроить бэкап.
2. Создать продукты/сервисы и владельцев по сервисам.
3. Настроить импорт и повторный импорт отчётов из GitHub Actions (Opengrep, Trivy, Gitleaks, ZAP, ORT) без дублей.
4. Настроить статусы по SSDLC: подтверждена / ложное / дубликат / принятый риск со сроком.
5. Проверить связь с GitHub Issues: создание задачи на исправление со ссылкой на находку (на пилоте; автоинтеграцию не считать готовой по умолчанию).
6. Описать инструкцию для разработчиков: где смотреть находки и как отмечать исправление.

## Что должно получиться
- Работающий DefectDojo с импортом из CI
- `docs/security/asoc.md`

## Критерии готовности
- [ ] Отчёты минимум трёх сканеров импортируются автоматически
- [ ] Повторный импорт не создаёт дублей
- [ ] У каждой находки есть сервис и владелец
- [ ] Разработчики знают, где смотреть свои находки
