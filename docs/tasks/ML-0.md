# ML-0 Идеи ML для авторизации, регистрации и соцсети v2.0

**Команда:** ML · **Исполнитель:** вся ML-команда (ведущий — ML-лид) · **Старт:** **сразу**

## Зачем
Сейчас в v2.0 делаем новый функционал: **авторизацию и регистрацию, профили пользователей и сервис соцсети** (посты, комментарии, ответы на комментарии, лайки, лента, посты пользователя). ML-команде нужно вместе обсудить, где ML может улучшить именно этот функционал, выбрать пару лучших идей и коротко описать, как их реализовать.

Идеи ищем **только для этого функционала**: регистрация, логины и никнеймы, профили, посты, комментарии, лайки, лента, поиск, модерация. Учебную часть платформы (курсы, домашки и т.д.) пока не трогаем.

## Что нужно на входе
- Объём работ: [docs/04-sprint-1-backlog.md](../04-sprint-1-backlog.md) и задачи BA-1…BA-3 (процессы регистрации, соцсети, профиля), DEV-20 (сервисы Auth / Users / Social и события)
- Соцсеть текущей платформы v1 (стена, профиль) — чтобы представлять, какие посты и комментарии пишут студенты
- Сервисы v2.0 обмениваются событиями (`user.registered`, `post.created`, `comment.created`, `like.added` и др.) — ML-сервис может подписываться на них

## Варианты для размышления
Это примеры, а не обязательный список. Можно предлагать свои.
- **Проверка логина и никнейма**: мат, оскорбления, скрытые значения (замена букв цифрами, транслит, «leet»), чтобы нельзя было зарегистрироваться с плохим логином.
- **Спам / не спам** в комментариях и постах.
- **Модерация контента**: токсичность, оскорбления, запрещённый контент; подсказка куратору, какие жалобы разобрать первыми.
- **Автотеги и категоризация постов**: например, «вопрос», «SQL», «backend», «вакансия».
- **Рекомендации**: «кого читать», «похожие посты».
- **Генерация и ассистент**: простой Т9 или автодополнение при написании поста, помощь сформулировать вопрос.
- **Умный поиск по постам**: поиск по смыслу (эмбеддинги), а не по подстроке.
- И другие идеи, которые придумает команда.

## Что сделать
1. Каждый участник знакомится с объёмом нового функционала и приносит 2–3 идеи.
2. Провести общую встречу ML-команды (1–1,5 часа): обсудить идеи всех вместе.
3. Собрать общий список идей (5–10 штук), по одной строке: что делаем и кому помогает.
4. Вместе выбрать 2–3 лучшие идеи: польза для пользователей, реальность реализации, есть ли данные.
5. Для каждой лучшей идеи тезисно описать реализацию:
   - какую проблему решаем и для кого;
   - где встраивается: при регистрации, при создании поста или комментария, в ленте, в поиске, в админке модерации;
   - подход: готовая модель, LLM или своя модель; на каких данных (открытые датасеты, разметка своими силами);
   - как работает технически: синхронный вызов (например, проверка логина при регистрации) или обработка событий (`post.created` → оценка → результат);
   - как поймём, что работает: 1–2 метрики (например, precision/recall, доля пойманного спама, CTR рекомендаций);
   - риски: ложные срабатывания, скорость ответа, стоимость, персональные данные.
6. Оформить результат одним документом и коротко показать продакт-владельцу и бэкенду.

## Что должно получиться
- `docs/ml/ideas.md`: список всех идей и 2–3 лучшие с тезисами реализации по пунктам шага 5

## Критерии готовности
- [ ] Встреча ML-команды проведена, в обсуждении участвовали все
- [ ] Есть список из 5–10 идей для регистрации, профилей и соцсети
- [ ] Выбраны 2–3 лучшие идеи, по каждой есть тезисы реализации, включая место встраивания и метрики
- [ ] Учтено: во внешние LLM — без идентификаторов пользователей, данные — только обезличенные (152-ФЗ)
- [ ] Документ показан продакт-владельцу и бэкенду
