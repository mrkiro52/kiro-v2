# ML-0 Изучить платформу v1 и подготовить идеи, куда встроить ML

**Команда:** ML · **Исполнитель:** ML-разработчик (можно нескольким, каждый берёт свои разделы) · **Старт:** **сразу**

## Зачем
Прежде чем проектировать ML/AI в v2.0, нужно понять, что уже есть в платформе v1, где у студентов и кураторов болит и где ML даст реальную пользу. Результат — основа для рабочей группы ML/AI ([docs/05-ml-ai-backlog.md](../05-ml-ai-backlog.md)) и приоритизации по RICE.

## Что нужно на входе
- Платформа v1: репозиторий https://github.com/mrkiro52/platform и работающая платформа (зарегистрироваться студентом и пройти основные сценарии)
- В репозитории v1: `docs/PLATFORM_AUDIT_V1_TO_V2.md`, `docs/ML_AI_OPPORTUNITIES.md`, `docs/kiro-system-design.html`, `backend/src/db.js` (схема данных), `src/data/programs/index.js`
- [docs/01-context.md](../01-context.md) — что такое v2.0 и потоки лагеря

## Что сделать
1. Изучить платформу как пользователь: программы по направлениям, мини-курсы, математика, домашки и проверка в админке, SQL-тренажёр, соцсеть, вакансии. Записать, какие действия делает студент и куратор.
2. Изучить данные: по `db.js` составить список таблиц и полей, которые потенциально пригодны для ML (ответы на домашки, результаты квизов и SQL-тренажёра, прогресс, активность, тексты материалов). Оценить объём и качество данных (хватает ли записей).
3. Изучить уже существующие идеи в `ML_AI_OPPORTUNITIES.md` и аудит; отметить, что актуально, что устарело, чего не хватает.
4. Найти точки применения ML по областям: проверка работ, обучение и рекомендации, поддержка студентов, работа кураторов, соцсеть и модерация, вакансии, аналитика и риски.
5. Для каждой идеи описать карточку: проблема и для кого, как ML решает, какие данные нужны и есть ли они, риски (качество, ошибки, 152-ФЗ), простая метрика успеха, грубая оценка трудоёмкости.
6. Предварительно оценить идеи по RICE (Reach / Impact / Confidence / Effort), выделить 3–5 лидеров и объяснить выбор.
7. Составить список вопросов к кураторам и студентам для следующего этапа (интервью).
8. Оформить результат PR-ом в `docs/ml/` и коротко представить команде.

## Что должно получиться
- `docs/ml/v1-research.md` — что изучено: сценарии, данные, выводы по платформе v1
- `docs/ml/ideas.md` — карточки идей (минимум 8–10) по шаблону из п. 5
- `docs/ml/rice.md` — таблица RICE с топ-3…5 и обоснованием
- `docs/ml/interview-questions.md` — вопросы для кураторов и студентов

## Критерии готовности
- [ ] Изучены все основные разделы платформы v1 и схема данных
- [ ] Минимум 8 идей, у каждой указаны данные, риски и метрика
- [ ] Для каждой идеи сказано, есть ли нужные данные уже сейчас
- [ ] Есть таблица RICE и выбор топ-3 с обоснованием
- [ ] Учтены ограничения: ML-команде только обезличенные данные; в внешние LLM — без идентификаторов (152-ФЗ)
- [ ] Результат представлен команде, замечания учтены

## С кем согласовать
Продакт-владелец, ИБ (по данным и 152-ФЗ), бэкендер (по данным)

## Вне объёма
Обучение моделей, прототипы, выгрузка реальных персональных данных. Интервью и прототипы — следующие задачи ML-группы.

> Идеи — предложения; окончательный выбор делает рабочая группа вместе с продакт-владельцем.

> Места, помеченные «предложение» или «предложить», — рекомендации, которые исполнитель проверяет и подтверждает с владельцем решения.
