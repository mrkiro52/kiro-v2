# DEV-21 Схемы БД

**Команда:** Бэкенд · **Исполнитель:** Бэкендер · **Старт:** после DEV-20 (#10)

## Зачем
У каждого сервиса своя PostgreSQL. Схемы — основа для миграций и для OpenAPI. Нужно заложить их так, чтобы потом не ломать при добавлении потоков.

## Что нужно на входе
- DEV-20 (границы сервисов и события)
- `backend/src/db.js` v1 — как сейчас хранятся пользователи и посты
- Глоссарий BA-6 и threat model SEC-1 — учесть по мере готовности

## Параллельные входы (не блокируют)
- SEC-1 (#11)
- BA-6 (#9)

Эти результаты делаются параллельно, часто другими командами. **Не жди их**: работай по объёму спринта и общим практикам, допущения запиши в своём документе. Когда результат появится — сверь и поправь (обычно это небольшие правки).

## Что сделать
1. Для каждого сервиса (Auth, Users, Social) описать таблицы: поля, типы, ключи, индексы, ограничения, статус удаления.
2. Учесть требования: идентификаторы (UUID), `created_at/updated_at`, мягкое удаление, аудит.
3. Определить, какие данные дублируются между сервисами и как синхронизируются (по событиям).
4. Описать стратегию миграций и план миграции данных из SQLite v1 (черновик).
5. Нарисовать ER-диаграммы для каждого сервиса.

## Что должно получиться
- `docs/db/auth.md`, `docs/db/users.md`, `docs/db/social.md` с ER-диаграммами и DDL-черновиком

## Критерии готовности
- [ ] Нет внешних ключей между БД разных сервисов.
- [ ] Все сущности из DEV-20 отражены в таблицах.
- [ ] Индексы покрывают ленту и посты пользователя.
- [ ] Архитектор и бэкендер подтвердили схемы.
