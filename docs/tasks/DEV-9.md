# DEV-9 Users: сервис профилей и приватности

**Команда:** Бэкенд · **Исполнитель:** Бэкендер · **Старт:** после DEV-5 (#18), DEV-6 (#19), DEV-7 (#20), DEV-22 (#17)

## Зачем
Users хранит профили: «о себе», ссылки, настройки приватности, публичные данные, которые видят другие. Профиль нужен соцсети (автор постов), поэтому сервис должен быть готов раньше Social.

## Что нужно на входе
- `contracts/users.openapi.yaml` (DEV-22)
- `docs/db/users.md` (DEV-21)
- `docs/requirements/profile.md` (BA-3)
- Событие `user.registered` из Auth

## Параллельные входы (не блокируют)
- BA-3 (#4)
- SEC-3 (#15)

Эти результаты делаются параллельно, часто другими командами. **Не жди их**: работай по объёму спринта и общим практикам, допущения запиши в своём документе. Когда результат появится — сверь и поправь (обычно это небольшие правки).

## Что сделать
1. Создать `services/users/` из шаблона, миграции по схеме DEV-21.
2. Реализовать создание профиля по событию `user.registered` (идемпотентно).
3. Реализовать API: получить свой и чужой профиль (с учётом приватности), обновить профиль, настройки приватности, ссылки.
4. Реализовать валидации и ограничения из BA-3 (длины, домены ссылок, санитизация текста по SEC-3).
5. Публиковать `user.profile_updated`, `user.privacy_changed`.
6. Обработать `user.deleted`: удаление/анонимизация профиля.
7. Тесты: юнит, интеграционные (включая правила приватности), контрактные.

## Что должно получиться
- `services/users/` с кодом, тестами, README
- Миграции БД

## Критерии готовности
- [ ] Все эндпоинты Users по контракту реализованы.
- [ ] Приватность работает: чужой пользователь не получает скрытые поля.
- [ ] Профиль создаётся автоматически после регистрации.
- [ ] Контрактные тесты зелёные, CI проходит.
