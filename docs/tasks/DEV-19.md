# DEV-19 Перенос пользователей и постов из v1

**Исполнитель:** Бэкендер / системный аналитик · **Этап 3 (MVP)** · **Зависит от:** SA-4 (#13), DEV-9 (#22), DEV-11 (#24)

## Зачем
Пользователи лагеря уже есть в v1. Чтобы не терять аккаунты, профили и посты, нужен безопасный перенос из SQLite в PostgreSQL новых сервисов.

## Что нужно на входе
- `backend/src/db.js` v1 (схема)
- Схемы БД v2 (SA-4)
- Решение по паролям из BA-1/SEC-2
- 152-ФЗ

## Что сделать
1. Описать соответствие таблиц v1 → сервисы v2 (Auth, Users, Social), правила преобразований.
2. Определить подход к паролям: перенос хэшей с повторным хэшированием при входе или принудительный сброс — по решению ИБ.
3. Написать скрипты миграции (идемпотентные), режим «сухого прогона» и отчёт расхождений.
4. Прогнать на копии данных на staging; сверить количество и выборочно содержимое.
5. Подготовить план переключения (окно, откат) и коммуникацию пользователям.
6. Следить, чтобы выгрузки для ML/тестов были обезличены.

## Что должно получиться
- `docs/migration/v1-to-v2.md`
- Скрипты в `infra/migration/`
- Отчёт пробной миграции

## Критерии готовности
- [ ] Пробная миграция на staging завершена без потерь.
- [ ] Скрипт можно запускать повторно.
- [ ] План отката описан и проверен.
- [ ] ИБ подтвердил обращение с паролями и ПДн.

## С кем согласовать
ИБ (SEC), Архитектор, Продакт-владелец

## Вне объёма
Перенос учебного контента, домашек, прогресса — отдельные задачи этапа 4.

> Места, помеченные «предложение» или «предложить», — рекомендации, которые исполнитель проверяет с владельцем решения.
