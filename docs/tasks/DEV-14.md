# DEV-14 Фронтенд: регистрация, вход, восстановление

**Команда:** Бэкенд · **Исполнитель:** Фуллстак · **Старт:** после DEV-4 (#16), DEV-6 (#19), DEV-8 (#21)

## Зачем
Первые экраны нового фронтенда: пользователь должен создать аккаунт, войти и восстановить доступ. Заодно создаётся каркас приложения.

## Что нужно на входе
- Макеты Figma (DEV-4)
- `contracts/auth.openapi.yaml`
- [`docs/design/kiro-design-system.md`](../design/kiro-design-system.md) — все цвета, шрифты и компоненты брать оттуда

## Параллельные входы (не блокируют)
- SEC-2 (#14)

Эти результаты делаются параллельно, часто другими командами. **Не жди их**: работай по объёму спринта и общим практикам, допущения запиши в своём документе. Когда результат появится — сверь и поправь (обычно это небольшие правки).

## Что сделать
1. Создать каркас приложения в `frontend/` (React + Vite): роутинг, клиент API по OpenAPI (генерация типов), хранение токена по SEC-2, обработка 401/refresh.
2. Реализовать экраны регистрации, входа, восстановления доступа, выхода.
3. Реализовать валидации форм, состояния загрузки и ошибок, доступность (клавиатура, подписи).
4. Защитить маршруты: гость/авторизованный.
5. Добавить тесты компонентов и e2e сценарий входа.
6. Подключить сборку и деплой на staging.

## Что должно получиться
- `frontend/` с каркасом и экранами
- Тесты

## Критерии готовности
- [ ] Пользователь регистрируется, входит, выходит и восстанавливает доступ на staging.
- [ ] Токены не сохраняются небезопасно (см. SEC-2).
- [ ] Экраны соответствуют макетам.
- [ ] Тесты зелёные.
